# 추가 모델 비교와 출력 계약 수정

`capability-results.json`의 GPT-6.1 Sol(low) 결과 10개를 검토했다. 첫 비교와 같은 질문·자료·지시를 사용했다. 단일 생성 5/5, 분리 생성 4/5가 응답에 성공했고, 분리 생성의 해외 사례는 `openai_503`으로 실패했다. 실패를 다시 뽑아 성공 사례로 바꾸지 않았다.

| 질문 | 단일 생성에서 확인한 차이 | 분리 생성 |
|---|---|---|
| 재회 | 조회와 답장을 구분하고 기다림을 멈추라는 답이 명확. 상대의 호감·제삼자를 단정하지 않음 | 같은 판단, 더 길고 반복됨 |
| 이직 | '사용자님이 한 일을 사용자님의 성과로'라고 화자를 정확히 유지. 월급 안정성과 공로 문제를 분리 | 비교 기준이 명확하지만 결론이 약해지고 설명이 늘어남 |
| 친구 | '내가 뭘 잘못했는지 묻는 것'과 '서운함을 말하는 것'의 차이를 짚음. 걸림돌의 논리가 뒤집히지 않음 | 좋은 핵심을 유지하나 더 길어짐 |
| 그림 | 모델의 message는 스타일의 핵심을 지키고 보여주는 방식을 시험하라는 직접적인 답. 화면 summary 첫 항목은 재능 위로로 돌아감 | 첫 항목이 더 직접적이고 노출과 반응의 차이를 짚음 |
| 해외 | 해외 생활을 우선 검토하고 복귀 조건을 확인하라는 답. '준비하지 않으셨다는 뜻은 아닙니다'로 모르는 것과 없는 것을 구분 | HTTP 503, 편집 평가 불가 |

단일 생성을 선택하되, 그림 사례에서 드러난 중복 출력 설계를 수정한다. 기존에는 message에 직접적인 답을 쓰고 summary 첫 항목을 다시 작성했다. UI는 summary를 보여주므로 좋은 첫 결론이 사용되지 않았다. 새 화면용 계약은 answer·reason·nextStep을 각각 한 번만 생성한다. 서버가 answer를 message와 첫 summary에 동일하게 넣는다. 금지어 치환이나 재생성으로 문장을 덮지 않는다.

이 계약 변경 뒤 개발 질문 5개, 아직 출력하지 않은 질문 10개, 그림 회귀 사례 1개, 열 장 배열의 시간·형식 사례 1개를 검증한다. 품질 기준에 미달한 경량 모델로 자동 전환하지 않는다. 제공자 오류가 나면 기존과 같이 질문·카드를 보존하고 재시도할 수 있게 한다.

이 평가는 실제 미래 예측이 맞았다는 검증이 아니다. 질문에 대한 직접성, 이해하기 쉬운 한국어, 카드와 사용자 사실을 구분하는 능력에 대한 자체 편집 평가다.
