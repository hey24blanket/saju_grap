# 사주 그랩: 해설에서 시작하는 사용 흐름

2026-10-15. PR #27. 상용 앱으로 전환하기 위한 첫 구현. 결제 가능한 상용 출시 완료 상태를 뜻하지 않는다.

## 사용자 흐름

1. 생년월일·달력·시간·대운 계산 기준을 입력하고 확인한다. 이름은 선택이다.
2. 오늘 화면에서 질문 없이 짧은 해설과 실천 하나를 읽는다.
3. 흐름에서 날짜·월 절기·연도·대운과 관심 분야를 고른다.
4. 해당 시기와 분야 그대로 상담한다. 서버가 분석 결과와 대화 이력을 보관한다.
5. 해설을 저장하거나 대화를 마치며 직접 메모를 남긴다.
6. 보관함에서 당시 내용을 다시 읽거나 대화를 이어간다.
7. 내 사주에서 정보 수정, JSON 내보내기, 현재 서버 연결과 이 브라우저 기록 삭제를 할 수 있다.

## 파동의 의미

`lib/waveReading.js`의 `phase-reading-v1`은 엔진의 십이운성 사실을 해설 언어로 투영한다. 기존 balanceImpact 점수에 집중/확산이라는 이름을 붙이지 않는다.

- 장생·목욕·관대·건록·제왕: 펼치는 흐름
- 쇠·병·사·묘·절·태: 모이는 흐름
- 양: 전환하는 흐름

이는 초기 전략 명리 가이드의 모으기/펼치기 취지를 구현한 **해석 규칙**이다. 사건 발생률·심리 측정·성공 점수가 아니다. 각 방식에 같은 가치를 부여하고 분야별 조언을 따로 제공한다. 파동 간격은 범주를 표현하며 실제 에너지의 양을 의미하지 않는다. 학술적 타당성 또는 전문가 검수를 완료했다는 주장은 하지 않는다.

모든 일자를 계산한다. 월·일의 상위 연/월 간지는 실제 해당 시점의 절기 기준 간지를 사용한다. 출생 시간 미상은 가능한 시각별 기둥을 비교해 불변인 기둥만 노출하며 시주·파동·종합 상담은 만들지 않는다.

## 서버 경계

- `/api/experience`의 analyze/chat/delete만 새 화면이 사용한다.
- `/api/chat`의 네트워크 진입도 같은 소유권 검사를 거친다. 내부 `runChat` 함수는 테스트와 서버 오케스트레이션 전용이다.
- 무작위 256-bit HttpOnly/Secure/SameSite=Strict 쿠키의 해시로 분석과 대화를 구분한다.
- 클라이언트의 engineFacts/history/state/provider override는 사용하지 않는다.
- 같은 requestId는 완료 응답을 재사용한다. 대화별 실행 잠금과 Firestore 트랜잭션으로 중복 실행을 막는다.
- 일일 상담 한도는 연결당 20회, IP당 60회다. 실패한 제공자 호출도 사용량에 포함한다. 이는 과금이나 구매 권한 시스템이 아니다.
- 첫 해설의 단순 활용 질문은 선택 시기의 근거만 전달하고 RAG/사례 검색을 생략한다. 개인 고민이나 후속 질문은 기존 종합 오케스트레이터를 사용한다.
- JSON 응답 검증 실패도 Gemini → OpenAI 대체 호출 안에서 처리한다. 응답 본문을 끝까지 읽을 때까지 타임아웃이 유지된다.
- 저장되는 사실 메모에는 사용자의 원문을 사용한다. 모델이 추가한 숫자 등을 사용자 사실로 굳히지 않는다.
- 서버 로그에는 제공자·모델·토큰 사용량과 요청 ID만 기록한다. 질문이나 출생 정보는 운영 로그에 쓰지 않는다.

필요 인프라: 기존 `getFirestoreClient()`가 사용하는 서버 자격 증명과 Gemini/OpenAI 환경변수. 제공자 모델 이름은 기존 환경변수를 유지한다.

## 상용 배포 전 남은 항목

1. 연결은 30일 뒤 접근 만료되지만 **만료 문서의 물리 삭제는 아직 자동화되지 않았다.** 루트와 하위 문서를 함께 지우는 정기 작업 및 재시도/감사가 필요하다. TTL로 루트만 삭제하면 하위 문서가 남으므로 그렇게 배포하지 않는다.
2. 보관함은 현재 브라우저 저장이다. 계정 로그인·기기 간 동기화·기존 계정 기록 이관은 별도 작업이다. UI에서도 기기 저장 범위를 명시한다.
3. 결제·구매 권한·환불·이용약관·개인정보 처리 절차와 상담 제공자의 데이터 보존 설정을 출시 정책에 맞춰 확정해야 한다.
4. 실제 iOS/Android, 키보드·스크린리더, 오프라인/업데이트 중 캐시 동작은 추가 검증이 필요하다.
5. 편안한 해설의 품질 평가, 전문가 검수, 사용성 인터뷰와 비용/지연 측정을 이어간다. RAG 검색 후보 수와 캐싱 최적화는 이번 변경에 포함하지 않는다.

기존 `docs/HANDOFF.md`의 9월 20일 화면 상태는 역사적 기록이다. 현재 변경은 사용자가 10월 15일 요청한 개선 작업의 별도 브랜치에 있다. 프로덕션에는 아직 반영하지 않는다.
