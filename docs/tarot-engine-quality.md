# 터틀 타로 v13: 읽은 뒤 다시 번역하지 않아도 되는 풀이

최우선 기준은 사용자가 한 번 읽고 질문의 답, 이유, 다음 판단 기준을 자신의 말로 바로 말할 수 있는가이다. 짧은 문장, 금지어 개수, JSON 성공률로 이 기준을 대신하지 않는다.

## 생성 구조

1. `tarotSymbols.js`의 그림 사실과 `tarotMeaningData.js`의 정·역방향 해석을 별도 자료로 제공한다. 78장에 각각 두 방향의 뜻이 있다. 그림 사실은 사람의 성격이나 미래의 증거가 아니다.
2. 해석은 질문에 대한 답, 판단을 바꾸는 구체적인 차이, 모르는 정보, 다음 행동, 카드별 적용을 만든다. 근거는 카드·방향·그림의 ID로 참조한다. 서버가 존재하는 카드와 올바른 방향인지 검증한다. 이는 참조 무결성 검사이며 해석의 의미가 옳다는 증명은 아니다.
3. 화면용 문장은 요약과 카드별 설명만 만든다. 그림 위 설명은 검증된 장면 설명을 서버가 붙인다. 상징마다 사용자의 삶에 관한 조언을 억지로 만들지 않는다.
4. 사용자 맥락에 생성된 추측을 사실로 추가하지 않는다. 기존 사용자 맥락을 보존하고 원래 사용자 발언과 이전 AI 답변을 구분한다.

## 비교 실험

고정된 합성 질문과 카드로 비교하며 실제 이용자의 상담 기록을 공개하지 않는다. `reference-readings.js`는 사람이 작성한 목표 원고이고 실험 모델에는 제공하지 않는다.

| 방식 | 호출 | 바뀌는 변수 |
|---|---:|---|
| single-openai | 1 | 한 응답에서 해석을 먼저 정하고 문장 작성 |
| staged-openai | 2 | 해석과 문장 작성을 별도 호출로 분리 |
| staged-gemini | 2 | 같은 분리 구조에서 제공자·모델 변경 |

첫 세 후보가 편집 기준에 미달해 동일한 프롬프트·자료로 GPT-6.1 Sol(low)의 단일/분리 생성도 비교한다. 모델명과 low 지원은 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-sol)로 확인했다. 품질은 문서의 성능 설명이 아니라 실제 원문으로 판단한다. (확인: 2026-10-07)

다섯 기준 질문에서 15개의 결과를 모두 남긴다. 실패한 호출도 결과로 기록하며 자동 재시도하거나 잘 나온 결과만 고르지 않는다. 검색 자료는 비워 세 방식에 동일한 근거를 준다. 선택 후 개발용 다섯 질문과 미사용 열 질문으로 추가 평가한다. 미사용 질문을 확인한 뒤 문구를 수정하면 그 질문은 더 이상 미사용 검증으로 부르지 않는다.

2026-10-07 첫 비교 실행은 15/15 생성·형식 검증이 성공했지만 배포 출력 폴더가 없어 정적 결과물을 게시하지 못했다. 답변 원문은 열람하지 못했고 빌드 로그의 시간·토큰 기록만 보존했다. 출력 폴더를 수정한 동일 조건의 두 번째 실행을 편집 평가에 사용한다. 결과 품질을 보고 재생성한 것이 아니며 첫 실행 기록도 삭제하지 않는다.

실험은 지정된 보호된 preview 브랜치의 빌드에서만 실행한다. 임의의 모델이나 질문을 유료 호출할 수 있는 공개 테스트 API는 만들지 않는다. 서버 API 키를 내려받지 않는다. 임시 buildCommand는 최종 병합에서 제거한다.

## 사람이 읽는 평가

요약, 카드 lead, 본문, 그림 설명을 모두 읽는다. 다음 항목마다 실제 문장을 근거로 통과 또는 실패를 기록한다.

| 항목 | 통과 조건 | 실패 예 |
|---|---|---|
| 한 번에 이해 | 다른 표현으로 바꾸거나 주어·인과를 보충하지 않아도 뜻이 잡힌다 | 성과가 자랄 환경, 귀국 뒤의 발밑 |
| 직접적인 답 | 첫 요약에서 질문에 답한다. 모르는 부분에만 조건을 단다 | 가능성과 균형을 살펴보세요 |
| 내 상황의 핵심 | 사용자가 말한 구체적인 행동 두 가지의 차이·갈등을 짚는다 | 누구에게나 맞는 위로·점검 목록 |
| 카드의 역할 | 방향과 자리마다 해석하는 일이 다르다. 조언을 세 번 반복하지 않는다 | 모든 카드가 연락을 멈추라고만 설명 |
| 근거의 한계 | 준비·속마음·감정·날짜를 만들어내지 않는다 | 귀국 계획을 말하지 않았으므로 준비가 없다 |

핵심 항목은 첫 두 항목이다. 문장이 쉬워도 질문을 회피하면 실패다. 단호해도 말하지 않은 사실을 만들면 실패다. '용하다'는 느낌은 남의 마음이나 미래를 아는 척해서 만들지 않는다.

최종 검증에서는 심각한 사실 조작·잘못된 방향·위험한 결정 지시가 없어야 한다. 이해와 직접성은 미사용 열 질문 중 최소 아홉 질문에서 모두 통과해야 한다. 품질이 비슷하면 적은 호출과 짧은 지연의 구조를 선택한다. 이 기준은 자체 편집 평가이며 실제 사용자 이해도 실험을 대신하지 않는다.

## 측정과 유지

스키마 검사와 편집 평가는 별도로 기록한다. 모델명, 호출 횟수, 입력·출력·총 토큰, 지연을 저장한다. 실제 청구 금액을 확인하지 못했다면 비용을 계산했다고 하지 않고 토큰과 호출량만 비교한다.

새 실패가 나오면 먼저 질문 오해, 근거 오류, 해석 오류, 문장 오류, 화면 중복 중 어디인지 분류한다. 문장 오류 때문에 카드 의미를 바꾸거나, 한 예외를 덮는 긴 지시를 계속 추가하지 않는다. 구조를 수정하면 기존 사례와 새 질문을 함께 확인한다.
