# 사주 그랩 2차 개선 — 계정과 기록의 연속성

## 사용자가 달라지는 지점

- 비회원 해설은 그대로 사용할 수 있다. 상단 로그인, 첫 화면의 기존 기록 안내, 내 사주·보관함의 계정 안내에서 이메일 계정을 연다.
- 이메일 인증을 마친 계정의 최신 사주와 보관함은 다른 기기에서 다시 열린다. 저장 버튼은 서버의 성공 응답 뒤에만 완료를 알린다.
- 비회원 기기 기록을 계정으로 옮기기 전에 대상 이메일·기록 수·이관 방식을 확인한다. 중단 후 재시도해도 중복되지 않는다. 보관하지 않은 진행 중 대화는 지우지 않는다.
- 옮긴 대화는 원문을 보관하며 새 질문은 같은 날짜의 새 상담으로 연결한다. 예전 기기 데이터가 서버의 상담 기억으로 승격되지 않는다.
- 로그아웃하면 계정 기록을 화면에서 지운다. 계정 보관함은 비회원 localStorage에 저장하지 않는다. 진행 중 상담만 UID와 서버 세대가 일치할 때 sessionStorage에서 복원하며, 다른 계정·로그아웃·전체 삭제 때 제거한다. 로그인 유지는 기본 해제, 사용자가 선택한다.
- 계정 기록 삭제는 비밀번호를 재확인한다. 기록만 비우기와 기록 삭제 후 로그아웃을 구분한다. Firebase 신원은 타로와 공유하므로 사주 그랩에서 Firebase 사용자를 삭제하지 않는다. 서비스 공통 로그인 계정의 완전 탈퇴 정책은 별도 출시 게이트다.

## 서버 계약

`api/experience`에 `account`, `record-save`, `record-import`, `record-delete`를 추가했다. 분석·상담도 인증 헤더가 있으면 계정 소유 공간에서 실행한다. 사용자 UID·권한을 JSON에서 받지 않는다. Firebase Admin의 `verifyIdToken(token, true)`로 서명·만료·취소·사용 중지 여부를 확인하고 이메일 인증 계정만 허용한다.

일반 저장은 서버 분석과 서버 대화 원문에서 생성한다. 기기 이관은 입력을 제한하고 해설 기준일로 재계산한 뒤 `source: device`, 대화 `readOnly: true`를 붙인다. 이관 기록은 상담 API의 신뢰된 분석·대화에 접근할 권한을 만들지 않는다.

보관함 40개, 개별 기록 85 KB, 요청 120 KB 한도. 목록 최대 3.4 MB로 응답 크기를 제한한다. 기록 버전·작업 ID·삭제 표시를 트랜잭션에서 검사해 재전송, 두 기기 충돌, 지운 기록의 되살아남을 막는다. 새로고침으로 다른 기기의 변경을 가져온다. 실시간 양방향 자동 병합은 제공하지 않는다.

모든 쓰기 트랜잭션은 부모의 세대·생성 시각·만료·삭제 상태를 확인한다. 삭제 중 도착한 AI 답변이나 이전 세대의 요청은 새 계정 기록을 다시 만들 수 없다. 삭제 자체도 전용 임대 잠금으로 중복 실행을 막는다.

## 보관 및 정리

- 비회원 서버 연결: 생성 후 30일.
- 계정 서버 기록: 계정 보관함의 마지막 접속 후 365일. 접속 갱신 쓰기는 하루 이내 중복하지 않는다.
- 계정 내 사주 계산·상담 원문·보관 기록도 같은 보관 기간을 따른다. 사용자 요청으로 그 전에 삭제할 수 있다.
- 만료되면 읽기·쓰기를 막는다. 재접속한 만료 계정은 기존 하위 데이터를 정리한 후 새 세대로 연다.
- `api/cleanup-experience`는 부모를 잠근 뒤 모든 하위 컬렉션을 삭제하고 마지막에 부모를 삭제한다. 실패한 부모는 만료 대상으로 남아 재시도할 수 있다. 사용량 카운터도 만료 후 삭제한다.
- Vercel Cron: 매일 13:10 UTC (22:10 KST). `CRON_SECRET`이 없거나 틀리면 실행하지 않는다. 프리뷰와 운영의 비밀값 및 신규 데이터 컬렉션을 분리했다. Cron 스케줄은 운영 배포에서 실행된다.
- 한 번에 컬렉션별 최대 100개 소유 공간, 카운터 400개를 조회하고 시간 한도 내 순차 처리한다. 대량 만료 시 후속 실행이 필요하므로 만료 즉시 물리 삭제를 보장하지 않는다. 실패 횟수는 로그와 503 응답으로 드러난다.

## 배포와 검증

운영 브랜치의 타로 개선 #28, Firebase 실행 호환성 수정 #29를 병합했다. `firebase-admin`은 운영에서 고정한 13.10.0 및 잠금 파일을 유지한다. 14.5.0은 `--no-experimental-require-module` 조건에서 `jwks-rsa → jose`의 `ERR_REQUIRE_ESM`이 재현되어 채택하지 않았다.

빌드는 타로 인증 검사에 사주 인증 검사를 추가한다. 사주 검사는 존재하지 않는 테스트 식별자를 읽는 방식으로 Firebase 인증 조회 권한을 검증한다. 사용자를 만들거나 이메일을 보내지 않는다.

로컬 회귀 검증: 기존 전체 테스트, 사주 경험 11개, 계정·정리 14개, 최신 타로 테스트 15개. 계정 테스트의 Firebase 신원과 Firestore는 주입형 어댑터이므로 실제 로그인 성공의 증거와는 구분한다.

배포 후 실제 확인 결과는 아래에 추가한다. 운영 전 필수 확인: 실제 이메일 인증 계정으로 두 기기에서 저장·재접속·로그아웃·기록 삭제, iPhone PWA, Firestore 클라이언트 직접 접근 규칙. 결제 기능은 이번 범위에 포함하지 않는다.

- Firestore 공개 REST 접근 확인은 이 실행 환경의 네트워크 타임아웃으로 완료하지 못했다. 클라이언트 보안 규칙 검증을 출시 게이트로 유지한다.
